# Prototyping Mobile App Final Projects in Figma

In class, we will use the **Prototyping Examples** Figma file to plan and prototype mobile app final projects. The goal is to move from an idea, to a user flow, to a screen map, and then to a clickable prototype that classmates can test.

Figma file: [Prototyping Examples](https://www.figma.com/design/NLaoQg5Ebk4UzOzpwwXQns/Prototyping-Examples)

## Class Agenda

### 1. Look at a finished student app prototype

We will start by looking at a previous student project by Htet Aung Lin. Pay attention to how the app feels when someone actually taps through it, not just how the screens look as static images.

- [Video: Htet Aung Lin using the app prototype](https://vimeo.com/898846329?fl=pl&fe=cm)
- [Portfolio case study: BMCC Student App](https://htauli-design.jimdosite.com/bmcc-student-app/)

Discussion prompts:

- What can we understand from seeing the app in motion?
- Which parts of the prototype make the app feel clear or confusing?
- What screens, buttons, or navigation choices would need to be planned before building the prototype?

### 2. User flows before screens

Before making every screen, we will sketch the path a user takes through the app. A user flow helps us decide what screens are needed and how someone gets from one place to another.

In the Figma file, look at the **User flow** example. We will talk through the basic diagram shapes:

- Rounded start/end shapes: where the experience begins or finishes
- Rectangles: pages, actions, or steps
- Diamonds: decisions or branches
- Arrows: the direction the user moves

Then we will practice in FigJam by making a quick user flow for one important task in the final project app.

Helpful resource:

- [Figma: Guide to prototyping in Figma](https://help.figma.com/hc/en-us/articles/360040314193-Getting-Started-with-Prototyping)

### 3. Static page diagram

After the user flow, we will make a simple page diagram: a map of the screens that need to exist. This is similar to the site maps we made for the website project, but now the screens are mobile app pages.

The page diagram should answer:

- What are the main screens?
- Which screens belong in the navigation?
- Which screens are reached by buttons or links inside another screen?

### 4. Build the basic prototype screens

In Figma, each major app page should become its own phone-sized frame. The screens can stay simple at first: page title, short placeholder text, a few colored areas, and buttons where needed. The point is to make the structure clickable before spending too much time polishing visual design.

We will use the example phone screens in **Prototyping Examples** to demonstrate:

- Creating a phone frame for each page
- Keeping content minimal while testing the structure
- Adding non-navigation buttons that lead to the right screens

Helpful resources:

- [Figma: Connect your prototype](https://help.figma.com/hc/en-us/articles/360040315773-Create-interactions)
- [Figma: View prototype connections](https://help.figma.com/hc/en-us/articles/4411431245335-View-prototype-connections)

### 5. Use a navigation component

We will make a navigation component so the same navigation can appear on every screen. The big idea is: link the nav items once in the main component, then place instances of that component on each screen.

We will look at this video workflow:

- [YouTube: Link Figma component navigation to screens](https://youtu.be/L22lDu3QX2c?si=JhwwPLfuaGbZdb4L)

In the **Prototyping Examples** file, there is also a copyable **Mobile Nav Bar** component. It uses icons from the Icons page and includes editable labels, icon swaps, and show/hide controls for nav items.

### 6. Prototype view and testing

Once the screens and navigation are set up, we will switch to Figma's Prototype view, check the connections, and test the app in presentation mode.

Testing questions:

- Can someone reach every important screen?
- Do buttons go where the user expects?
- Is the navigation consistent from screen to screen?
- Is anything missing from the flow?

Helpful resources:

- [Figma: Play your prototypes](https://help.figma.com/hc/en-us/articles/360040318013-Present-designs-and-prototypes)
- [Figma: Share files and prototypes](https://help.figma.com/hc/en-us/articles/360040531773-Share-files-and-prototypes)

### 7. Breakout room partner test

At the end, you will share your prototype link with a partner in a breakout room. Your partner should click through the app and tell you where they feel confident, confused, or stuck.

Before sharing:

- Open the prototype with **Present**
- Use **Share** or **Share prototype**
- Copy the link
- Make sure your partner has permission to view it

After testing, write down one thing to fix before continuing with the final project.
